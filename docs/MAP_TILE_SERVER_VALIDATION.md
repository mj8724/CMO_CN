# 中文地名瓦片加载修复验收

验证日期：2026-10-18。实机为 Steam BuildID 25865381 / 游戏 Build 1900.23，Windows、.NET Framework 4.x 运行时。

## 问题与修复

游戏下载和本地中文标签请求共享 CLR ThreadPool。下载工作占住 worker 后，本地服务将请求再次排入同一个池，会出现初始少量瓦片正常、后续中文标签停止加载的情况。

现有专用监听线程直接处理请求，避免依赖共享 worker。每次网络读写设 1500 ms 超时；仅接受有效 GET XYZ 标签请求，缩放级别为 0–22；诊断只记录前 16 个请求。此超时约束单次读写，并非整个连接的总截止时间。

沿用仓库现有 321 条宏观地名及 4,287 条城市数据。功能改动限于地图服务，测试和验收文档随附。

## 独立回归

从源码重新编译引擎及 `MapTileServerTests.cs`。每项使用独立 Framework 进程及全新 WWP fixture，35 秒超时，子进程全部等待退出。

| 模式 | 结果 |
| --- | --- |
| starvation | 28 个 worker 全部占满，available=0；仍返回有效 PNG，释放后继续正常。原实现同条件下读取超时。 |
| protocol | z=3/7/9/22 的已知地名返回 256×256 非透明 PNG；非法路径、越界坐标、非 GET 请求返回 400。 |
| idle | 不完整请求超时关闭，后续正常请求仍能成功。 |
| batch | 8 个并发客户端和 20 次连续请求通过，采样日志恰为 16 条。 |

四项全部通过。运行方法见 [测试说明](../src/tests/README_MapTileServer.md)。测试仅调用地图服务，不初始化游戏或运行安装器。

上述重访视图使用已有标签缓存；另向正在运行的游戏标签服务请求 z=3/7/9/22 的已知 WWP 地名瓦片，全部 HTTP 200、256×256 且非透明。游戏随后正常退出。
