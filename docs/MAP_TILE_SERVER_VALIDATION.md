# 中文地名瓦片加载修复验收

验证日期：2026-10-18。实机为 Steam BuildID 25865381 / 游戏 Build 1900.23，Windows、.NET Framework 4.x 运行时。

## 问题与修复

游戏下载和本地中文标签请求共享 CLR ThreadPool。下载工作占住 worker 后，本地服务将请求再次排入同一个池，会出现初始少量瓦片正常、后续中文标签停止加载的情况。

接受连接与处理请求分别使用专用线程：1 个接受线程、4 个工作线程、最多 64 项等待队列，不依赖共享 worker。每个连接的首行总预算为 1500 ms，从接受时开始，包含排队时间；读取每个字符前后检查单调时钟，按剩余预算设置读取超时。零散字节不能延长预算，首行最多 1024 个字符。队列已满或请求过期时关闭连接；响应写入另有 1500 ms 单次操作超时。

仅接受有效 GET XYZ 标签请求，缩放级别为 0–22；诊断共采样前 16 个请求、拒绝及错误，写入由地图服务私有锁串行化。过载时允许拒绝请求，资源上限不保证任意负载下全部请求成功。

沿用仓库现有 321 条宏观地名及 4,287 条城市数据。功能改动限于地图服务，测试和验收文档随附。

## 独立回归

从源码重新编译引擎及 `MapTileServerTests.cs`。每项使用独立 Framework 进程及全新 WWP fixture，35 秒超时，子进程全部等待退出。

| 模式 | 结果 |
| --- | --- |
| starvation | 28 个 worker 全部占满，available=0；仍返回有效 PNG，释放后继续正常。原实现同条件下读取超时。 |
| protocol | z=3/7/9/22 的已知地名返回 256×256 非透明 PNG；非法路径、越界坐标、非 GET 请求返回 400。 |
| idle | 不完整请求超时关闭，后续正常请求仍能成功。 |
| batch | 8 个并发客户端和 20 次连续请求通过，采样日志恰为 16 条。 |
| multi-idle | 3 个半行连接存在时，正常标签 GET 约 5 ms 返回。 |
| trickle | 每 250 ms 发送一个字节，连接仍约 1507 ms 后关闭，随后正常请求成功。 |
| pressure | 96 个空闲连接中 28 个提前关闭，最终全部关闭；进程线程数 13→13，清理后正常请求成功。 |

七项全部通过。运行方法见 [测试说明](../src/tests/README_MapTileServer.md)。测试仅调用地图服务，不初始化游戏或运行安装器。客户端超时包含系统调度容差；1500 ms 为服务端预算，不是实时关闭保证。

新增的三个回归在此前单线程服务上均先复现失败，再验证修复通过：多个半行连接阻塞正常请求、零散字节不断刷新单次读超时、连接数量缺少应用层上限。此前四项通过并不能覆盖这些问题。

PR 最终候选基于上游 `269cc3b72da30c60015a00eb9400b5b0fc5466bc`，保留其数据库与航空作业更新。地图服务段与本地最终修复逐字相同，其他代码与该上游提交逐字相同（统一 LF 后比较）。本地修复和合并候选均重新编译，并分别通过上述七项测试。

PR 最终候选源码 SHA256：`FA4D5C2E5D6D1F4178B9E5863451F995804C020DBE57015768C515C46E3294AC`。

两次实机复查的重访视图均使用已有标签缓存；另分别向当次运行中的标签服务请求 z=3/7/9/22 的已知 WWP 地名瓦片，全部 HTTP 200、256×256 且非透明，确认当前服务能够生成标签。

本地部署环境还完成一次恢复原版与重新应用：365 项核心文件、7,328 个原缓存文件（10,642,894 字节）逐项 SHA256 校验通过；1,369 个中文瓦片完整保留。该检查用于确认本地部署可逆，PR 的代码范围仍为地图服务与测试。最终保持本地汉化启用。
